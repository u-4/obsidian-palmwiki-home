# PalmWiki Home Lite — 試用MVP 0.1.0

既存のPalmWiki Home 0.6.1を変更しない、別ID `palmwiki-home-lite` の試用版です。
本番への導入・mainへのマージ・正式Releaseはまだ行いません。

## 最初の試用

1. Obsidianを終了します。配布ZIPを展開し、macOSのターミナルから展開フォルダの `install-macos.command` を `bash` で実行します。Node.jsやnpmの導入は不要です。
2. 選択画面で既存の `PalmWiki_LocalTest` を指定します。他のVaultには配置しません。コピーするのは3成果物だけで、旧LiteがあればVault外に退避し、コピー前後にSHA-256を照合します。
3. テストVaultを開き、コアプラグインのBasesを有効にします。旧PalmWiki Homeを無効、新しいPalmWiki Home Liteを有効にします。2hop改造版はそのままにします。
4. Liteの設定で、検索ボタンにOmnisearchのVault search、移動ボタンにAnother Quick Switcherの使いたい検索コマンドを選択します。未導入のプラグインを自動導入・有効化しません。移動ボタンの初期値は未設定です。
5. タブ上部のHomeを押します。初回に限り `PalmWiki Home.base` を作成します。既存の同名ファイルは開くだけで上書きしません。別の既存.baseも設定可能です。

## 実装した範囲

- Basesが抽出・フィルター・並べ替えを担当。初期Homeは全Markdownの更新日時降順。
- テキストプレビュー付きカード。DOMは1ページ60件まで、前へ・次へで移動。
- 対応環境では画面付近のカードだけ本文を読み、同時読込は最大2件。512 KiB超のノートはプレビューを省略して通常に開けます。
- プレビューは最大280文字のプレーンテキスト。画像、外部埋め込み、MarkdownレンダリングはMVP対象外。
- 独自の全文検索索引、PageRank、全文永続キャッシュ、Vault全体の本文先行取得、Reactの実行時依存はありません。起動だけでは.baseの作成も検索実行も行いません。
- Markdown・Bases・Canvas等、通常のワークスペースタブ上部にHome／検索／移動を配置します。サイドバー内ビューとHover popover、設定ダイアログ、OS画面は対象外です。標準ヘッダーが非表示でも独立した細いバーを使います。
- Homeは同じタブに.baseを開きます。ピン留めタブは維持して新しいタブに開きます。Home内のボタンは先頭ページへ戻します。
- 検索・移動はユーザーが選択した既存コマンドを起動するだけです。未登録なら通知し、別コマンドへの暗黙の切替はしません。
- ノートの作成・移動・内容変更、frontmatter追加、既存プラグイン設定変更、旧キャッシュの読込・削除はしません。

外部プラグイン自身の索引処理は別です。Omnisearchを有効にしたままなら、Omnisearch自身の起動負荷が残る場合があります。Liteが外部プラグインの索引やライフサイクルを変更するわけではありません。

## フィルター

Basesのフィルター／ビュー設定でタグ・プロパティなどを選びます。既存のPARA分類を再利用してください。今回、既存ノートへの分類プロパティの一括書込や独自のPARA切替タブは実装していません。Basesの保存済みビューで切替可能です。グループ指定時はグループ順にカードを連結し、専用のグループ見出しは表示しません。

## 検証

開発コンテナのNode.jsで構文検査と15件のAPI/DOMダブルによる自動テストが成功しました。1万件の合成エントリーでもカードDOM60件、同時本文読込2件、画面外プレビュー抑制、古い非同期結果の破棄、Home作成の排他、ツールバーの重複・清掃などを確認しました。

これは実Obsidianの描画性能やiPadでの動作確認ではありません。既存TypeScript版の `npm run build` / `npm run eslint` と正式レビューは未実施です。既存版のソース・依存関係・ビルド設定は変更していません。

### 必要な実機テスト

- 最近更新したノートが先頭、作成／編集／削除／改名の反映、60件ページ境界。
- Markdown、Bases、Canvas、Graph、PDF等を開き、Home／外部検索／移動ボタンが動くこと。
- ノートを開いた直後の2hop、ピン留め、戻る・進む、分割表示、ポップアウト、プラグイン再有効化。
- 日本語タイトル・本文、ライト／ダーク、狭いペイン、iPad横縦・Split View。
- iPadのオフラインとアプリ切替からの復帰。同じノートに復帰できるかはOSとObsidian側の試験が必要です。
- Lite単体と2hop併用、それぞれに外部検索を加えた場合の起動・復帰・追加反映の差。

MVPのページ番号はビュー再生成時に先頭へ戻ります。独自の長期状態復元は未実装です。戻る・進む、iPadプロセス再起動時の位置復元、特殊テーマ／他プラグイン独自ビューのバー位置は未検証です。

## 戻し方

Liteを無効にして旧PalmWiki Homeを有効にすれば元の構成に戻ります。旧版の設定・索引ファイルは変更しません。初回Homeクリックで新規作成した.baseが不要なら、そのファイルだけを後で手動削除してください。既存だった.baseは削除しないでください。Liteを無効にしても.baseはノート本文を書き換えません。

## 開発の継続

リポジトリの `AGENTS.md` と `PROJECT_CONTEXT.md` に従ってください。今回のMVPはこの `lite/` のみで独立しています。追加のnpm依存はありません。Node.js 22以上で:

```sh
node lite/build.mjs
```

`lite/dist/palmwiki-home-lite/` に `main.js`・`manifest.json`・`styles.css`、その親に照合用 `SHA256SUMS` が出ます。`main.cjs` はCommonJSの実行可能なソースで、ビルドは構文・テスト・版整合性の検証と3成果物の組立てです。生成物はGit管理しません。`lite/package.json`・manifest・versionsはLiteの版、ルートの版番号は従来プラグインの版です。正式リリース前には既存の必須チェックと実機検証を完了してください。

コマンド起動だけはObsidianの公開型APIに無い `app.commands` を小さな互換境界として使っています。存在確認と失敗通知を入れ、他プラグインの内部索引・DOM・設定には触れません。

今回のcommitには `[skip ci]` を付け、Actions設定そのものは変更しません。CI未実行をPASSと扱わず、保護ルールの変更や迂回マージはしません。次担当は実機のMVP検証結果を優先し、検索索引の再追加は行わないでください。iPad復帰とPARA専用UIは次段階です。
